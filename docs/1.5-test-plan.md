# 1.5 test plan, round A

Everything below is deployed and compiles but hasn't run in the game yet. Quit Claude Desktop from the tray and reopen it
first (new tools and descriptions). The host DLL changed too, so start the game fresh. Make a game-menu save before
starting. Steps 1-3 work with the game closed.

Two setups: **Steam** (the large collection, Vortex) and **GOG** (vanilla, MO2). Where a step says "GOG", it is there to
test MO2 or a plain load order. Don't return to the main menu from a loaded game on the Steam collection (known crash on
teardown; see step 9): use RestartGame, which quits to the desktop.

## 1. Creation Kit and script patching (FEAT-270..272), game can be closed

1. `GetCreationKit`: expect the 2011 Creation Kit at `C:\Steam\steamapps\common\skyrim`, `edition: LE`, its compiler, the
   source folders with counts, and `vanillaSources.ready: false` the first time.
2. `PrepareScriptSources` (dry run), then `dryRun: false`: unpacks into `...\SkyLinkAI\Build\vanilla-sources-LE`. Then
   `GetCreationKit` again: `ready: true` and a flags file.
3. `GetScriptSource("mihail_wendigo_script2")`: the mod's source with where it came from, or `compiledOnly` if it ships none.
4. Recompile the wendigo fix: `CompileScript("mihail_wendigo_script2", sourcePath: "<Skyrim>\_Claude\patches\WendigoUpdateFix\Source\Scripts\mihail_wendigo_script2.psc", project: "WendigoUpdateFix")`.
   Expect `compiled: true` and a .pex. Then make a deliberate error (remove an `EndFunction`, pass it as `source`) and check
   the error comes back with a line number.
5. `PackageOverrideMod("WendigoUpdateFix", overrides: "Mihail's Wendigo")` dry run, then `dryRun: false`: a zip with
   `Scripts/`, `Source/Scripts/` and a readme. Compare it with the hand-made `WendigoUpdateFix.zip` in Downloads.
6. GOG (MO2 closed): `PackageOverrideMod(..., installToMo2: true, dryRun: false)`: the mod folder appears in MO2 at top
   priority, and `modlist.txt` has a `.skylink-*.bak` beside it.

## 2. Crash reports (FEAT-279, FEAT-287), game can be closed

1. `GetCrashLog()` on the newest report (Community Shaders, 11-20 12:04): `analysis.knownPatterns` names the Community
   Shaders snow/fresnel signature; `faultingModule: CommunityShaders.dll`.
   `secondOpinion` points at Phostwood's analyzer with the report's path.
2. `GetCrashLog(index: 1)` (OStim scene menu) and `index: 2` (the tree mesh): each matches its own signature.
3. The Inner Warmth log, if Crash Logger's folder still has it (it was restored to Downloads; copy it back to try).
4. `windowsDump`: only appears when a Windows dump is newer than the newest Crash Logger report. To see it, the 11-19 dump
   is older, so this shows up only after the next shutdown crash. Optional: check `C:\CrashDumps` is still the LocalDumps
   folder (`scripts/minidump-summary.py` reads a dump from WSL).

## 3. Plugins, load order, LOOT and cleaning (FEAT-273..276, 286, 288), game closed

1. `GetLoadOrderLimits`: expect about 251/254 full and 4,088/4,096 light on Steam (both flagged close to the limit) and a
   page of light candidates. On GOG: small numbers.
2. `GetPluginInfo("Unofficial Skyrim Special Edition Patch.esp")`: masters, record counts by type, light verdict
   ("only by compacting").
3. `CreatePlugin("SkyLinkTest", records: [{"type":"GLOB","editorId":"SkyLinkTestGlobal","valueType":"short","value":1}])`
   dry run, then `dryRun: false`: `roundTrip.ok: true` and a file in `...\SkyLinkAI\Build\SkyLinkTest`. (CreatePlugin's
   description has the exact record format.)
4. `CheckPluginDependencies("<path of the new .esp>")`: no masters problem.
5. `InstallPlugin("SkyLinkTest")` dry run on Steam: `manager: Vortex` and the instruction to install it in Vortex. On GOG
   (MO2 closed): `manager: MO2`, then `dryRun: false`, and see it in MO2. `SortLoadOrder()`: the MO2 note.
6. `GetLootNotes()`: the summary (on Steam about 7 missing requirements and 50 dirty), and the masterlist age note.
   `GetLootNotes("Update.esm")`: dirty, with SSEEdit as the tool.
7. `CleanPlugins()` (dry run): the list, with base game and Creation Club files skipped. Only if SSEEdit is installed and
   you're happy to clean one plugin: `CleanPlugins(plugins: "<one small dirty mod plugin>", confirm: true)`, then check the
   backup exists and `matchesLootClean`.
8. GOG step 4.4's reload experiment uses the plugin from step 3.

## 4. Session (FEAT-278, FEAT-015, FEAT-277)

1. Steam, in game: `RestartGame()` (dry run): the steps and "with skse64_loader.exe". Then `confirm: true`: it saves,
   quits to the desktop, relaunches. Then `WaitForSkyrim(timeoutSeconds: 600)` and `LoadSave` with the name it gave.
2. GOG (MO2 running): the same; the dry run should say "through MO2 (SKSE)" (or why it can't).
3. GOG, fresh launch, at the main menu: `StartNewGame("RiverwoodSleepingGiantInn")`: a new game in the inn.
4. GOG, fresh launch, at the main menu: the reload experiment. Make a tiny plugin (step 3's CreatePlugin), install it,
   then `ReloadContent(checkPlugin: "<name>.esp")`: report the verdict, and anything odd (crash, missing menus).

## 5. Runaway scripts (FEAT-280)

2. `StopRunaway(entry)` dry run: the objects (names, form IDs, stack counts). Then `dryRun: false`: unregistered count and
   `stacksAfter5s`. A minute later, `StackReport` again: falling?

3. `GetQuestInfo`/`GetQuestStages` on a quest whose objective names a person or place: names filled in, no `<Alias=...>`.

## 8. SkyLink's cost and a second client (INFRA-007, INFRA-023)

2. With Claude Desktop connected: from WSL, `scripts/pipe-call.sh ping` and `scripts/pipe-call.sh get_skylink_cost` both
   answer (they used to wait for Claude Desktop to let go). Claude Desktop keeps working at the same time.

## 9. Remediation (fixes from 1.3/1.4 never proven in game)

   (`SetFaceSliders` on any slider): expect a refusal naming the menu.

   before it's equipped; spells the character doesn't know aren't equipped.
3. BUG-087: set `bAlwaysActive=0` in Skyrim.ini (or use a game where it's off), click away from the game, call any tool:
   the error names the background window and bAlwaysActive. Set it back after.

   finds its meshes.
